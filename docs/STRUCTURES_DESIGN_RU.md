# Forest Studio 2.0 — техническая концепция Structures, природной генерации и редактора маски

**Статус документа:** проектирование будущей версии **после v0.4.6**. Функции из этого файла **не включены** в релиз v0.4.6.

## 1. Смысл структур

Структура (**Forest Structure**) — сохранённая пользователем композиция нескольких существующих `.object` X-Ray SDK. Пользователь расставляет в 3ds Max 5–20 объектов в нужных позах: например, один поваленный ствол, два пня, несколько кустов и камней. Forest Studio запоминает **относительные координаты, повороты, масштаб и правила посадки**; сами SDK-модели не копирует. Генератор размещает готовую композицию целиком, но допускает индивидуальную подстройку её элементов к террейну.

Структура не равна «группе». **Группа** хранит взаимозаменяемые модели, между которыми генератор делает выбор по весам. **Структура** хранит заранее заданную пространственную композицию, все (или часть необязательных) элементы которой размещаются совместно.

Примеры структур: сухостой с порослью, молодая рощица, завал из деревьев и ветвей, россыпь камней, болотная кочка с тростником, группа кустов вокруг упавшего ствола, прибрежный коряжник, «лесной край» с постепенным переходом к поляне.

## 2. Предлагаемый интерфейс — шесть разделов

```text
Forest Studio
├── Проект        ─ корень SDK, terrain, seed, пути, плотность мира
├── Библиотека    ─ все .object из trees, THM-превью, поиск
├── Маска         ─ RGB/Alpha, редактирование и пипетка
├── Структуры     ─ библиотека шаблонов, создание, состав, preview
├── Расстановка   ─ группы, плотность, кластеры, фильтры рельефа,
│                    выбор структур и настройки их частоты
└── Экспорт SDK   ─ .part, диагностика и отчёт
```

### Вкладка «Структуры»

Левая панель: карточки структур с названием, превью и количеством объектов, папками/тегами («лес», «болото», «камни», «мёртвый лес»). Центр: состав структуры — дерево моделей, иконка `.object`, состояние ссылки SDK. Справа: настройки якоря, высотной адаптации, радиуса занимаемой площади и параметров каждого элемента. Снизу: **«Создать из выделенного»**, **«Изменить в сцене»**, **«Сохранить как…»**, **«Проверить ссылки SDK»**, **«Удалить структуру»**.

Необходимо поддержать поиск, сортировку, дублирование, импорт/экспорт пакетов структур, контекстное меню, предпросмотр размеров и списка элементов. При экспорте структуры для другого маппера предупреждать, что `.object` должны существовать в его SDK.

### Вкладка «Расстановка»

Отдельный блок **«Использовать структуры»**: галочка, список отмеченных шаблонов и частота их появления (структур/га) или заданное количество; относительный вес каждого шаблона, допустимые зоны маски, расстояние между экземплярами структур, дополнительный радиус безопасной зоны. В первом выпуске структуры размещаются **до отдельных растений**, чтобы обычные группы заполняли пространство вокруг композиций, не сталкиваясь с ними.

Кнопки: **Preview структур**, **Генерировать выбранные**, **Удалить сгенерированные структуры**, **Перегенерировать структуру/всё**. Команды удаления должны быть основаны на устойчивых метках, а не имени узла.

## 3. Создание структуры из сцены: UX и алгоритм

1. Пользователь импортирует нужные `.object` в Max посредством существующей библиотеки или использует уже загруженные объекты с корректным `User Property ref_name`.
2. В сцене настраивает **каждый** объект вручную: передвигает, крутит, масштабирует. Рабочую площадку можно держать около `[0,0,0]`, но это не должно быть обязательным условием.
3. Выделяет объекты и нажимает **«Структуры → Создать из выделенного»**.
4. Открывается **Мастер структуры**: имя, категория, источник превью, выбор **якоря** (центр выделения / центр bounding box / текущая позиция курсора / пользовательский Dummy); список рефов и режим нормали каждого элемента; размер структуры, проверки отсутствующих SDK-ссылок.
5. Нажимает **«Сохранить»**. Scene objects не удаляются, не пересоздаются и не перемещаются. Только записывается версия JSON, PNG-превью создаётся отдельно и необязательно.
6. Новая карточка сразу появляется в библиотеке. После закрытия Max структура остаётся на диске.

**Якорь** — ключевой элемент. Пусть матрица его преобразования `A`, а матрица объекта `Wᵢ`. В файл сохраняем локальное `Lᵢ = inverse(A) × Wᵢ` (или эквивалентный TRS в едином соглашении о порядке умножения). При вставке экземпляра с матрицей `S`: `W'ᵢ = S × Lᵢ` до коррекции высоты и нормали. Точность матриц и исходных единиц должна сохраняться. Нельзя просто вычитать позиции объектов и терять их вращения/неравномерные масштабы.

Возможность **«Редактировать структуру»**: создать в сцене отдельные временные прокси/объекты выбранной структуры в собственном слое, отметить метками `fs_structure_edit`/`fs_structure_id`, изменить, затем «Обновить структуру»; не смешивать с уже сгенерированным лесом и не экспортировать временную рабочую копию. «Отмена» удаляет только временный редакторский слой.

## 4. Индивидуальная привязка к нормали и рельефу

Для **каждого** элемента мастер хранит:

- `surfaceMode`: `keep_relative` (жёсткая композиция) / `follow_height` (каждая модель встаёт по высоте террейна) / `follow_normal` (высота + наклон локальной оси Z к нормали).
- `normalBlend`: от `0` до `1`; `0` — без коррекции, `1` — полное выравнивание. Значение индивидуально для каждой модели.
- `keepAuthoredYaw`: сохранять авторское направление в плоскости XY при коррекции наклона (по умолчанию да).
- `zOffsetMeters`: дополнительный вертикальный сдвиг после проекции, чтобы камень мог частично войти в грунт.
- `maxTiltDeg`: предел наклона (например 10° для деревьев, 65° для камней).
- `required`: если ссылка отсутствует или место недопустимо, пропустить всю структуру (по умолчанию да), либо только необязательный элемент.

**Три типовых режима для структуры:**

- **Жёсткая:** сохранять все взаимные высоты и углы относительно якоря; вертикаль и нормаль рассчитывать только для якоря. Подходит для рукотворных конструкций и жёстких завалов.
- **По поверхности:** каждый элемент проецируется на рельеф отдельно; подходит для рощи на склоне, но относительная геометрия по Z меняется.
- **Гибридная (по умолчанию):** якорь ставится на поверхность, группы «следовать поверхности» получают свою высоту/нормаль; прочие сохраняют авторскую относительную высоту и позу. Позволяет поставить ровные стволы и наклонные камни в одной композиции.

Вращения хранить **кватернионами** или полными 3×3 матрицами; не пересчитывать в Euler при сохранении и загрузке редактора. Нужны тесты на отрицательный/неравномерный масштаб, круговые повороты, нормали на крутом склоне и сохранение авторских наклонов. X-Ray `.part` получает итоговую позу через существующую проверенную процедуру конвертации координат Max→SDK.

## 5. Дисковый формат и расположение файлов

Предлагаемая библиотека по умолчанию:

```text
C:\Projects\ForestStudio\UserData\Structures\
├── dry_fir_patch.foreststruct.json
├── dry_fir_patch.preview.png
├── creek_rocks.foreststruct.json
└── ...
```

Путь **настраиваемый**, можно перенести библиотеку на другой диск; пользовательские структуры **не должны исчезать при обновлении программы**. Если установочный архив заменяет рабочую папку целиком, каталог UserData необходимо сохранять или размещать отдельно в `%LOCALAPPDATA%\ForestStudio\Structures` с возможностью экспорта/импорта.

Требования к формату: открытый JSON, UTF-8, `schemaVersion`, стабильный UUID, человекочитаемое имя, метка автора, единицы `game_m`, origin/pivot, список ссылок `ref_name` относительно корня `rawdata\objects` без `.object`, матрицы/TRS, атрибуты нормалей, footprint, пользовательские теги, время сохранения. **Никаких абсолютных путей `D:\ixray\sdk` в самом файле.** В структуру не включать меши, материалы, текстуры, THM; изображения превью — отдельные необязательные файлы.

Пример схемы в отдельном `example_dry_fir_patch.foreststruct.json`. Пока JSON — **проект будущего формата**, нынешняя v0.4.6 не должна его открывать.

Сохранение — через временный файл и атомарную замену; перед редактированием делать `.bak`. Невалидные JSON-файлы не удалять автоматически. При загрузке проверять `schemaVersion` и реальное существование всех `ref_name` в SDK, выделять отсутствующие красным и предлагать заменить ссылку. Нельзя молча подменять модель по совпадению короткого имени.

## 6. Генерация структур (специальные правила)

**Пайплайн:**

1. Проверка SDK, маски, валидности структур и трансформаций, подготовка LOD требуемых моделей.
2. Построение допустимых зон маски по RGB+Alpha, фильтров рельефа (высота, уклон, ориентация), seed.
3. Предварительный подбор кандидатов якорей структур по заданной частоте/га и весам шаблонов.
4. Для каждого кандидата вычислить будущие мировые позиции всех элементов и нормали, проверить их условия рельефа и допустимость маски.
5. Проверить **footprint** структуры: отсутствие конфликтов с другими экземплярами и общими зонами исключения, минимальный отступ от границы маски (можно задавать процент допустимого пересечения).
6. Если валидно — резервировать область, затем создавать экземпляр. Если невалидно — ограниченно повторять поиск другой точки, затем записывать причину отказа.
7. Только затем расставить одиночные деревья по обычным группам с учётом зарезервированных областей и межгрупповых расстояний.
8. Итоговый отчёт: структура / экземпляры / число компонентов / причины отклонений / суммарные объекты / время / seed.

**Детерминированность:** при неизменных маске, террейне, параметрах, SDK-каталоге и seed результат должен повторяться. Для структур — независимый RNG-поток от индивидуальных групп, чтобы изменение веса одного шаблона не обязательно перемешивало весь лес.

**Безопасность:** помечать каждый созданный узел `forest_generated=true`, `fs_source_kind=structure`, `fs_structure_uuid`, `fs_structure_instance_uuid` и `ref_name`. Очистка конкретного экземпляра структуры — по UUID экземпляра, всей генерации — только по `forest_generated`. Undo-блоки и отмена длительной генерации обязательны; не удалять исходники/LOD и рабочую сцену захвата структур.

**Экспорт:** результат структур разворачивается в обычные X-Ray scene objects; сам шаблон `foreststruct.json` не записывается в `.part`. Действующий exporter получает реальные итоговые матрицы/ref_name. Проверять размер слоёв и производительность для 50–100 тыс. экземпляров.

## 7. «Естественные скопления и поляны» — отдельный режим групп

Для обычных групп три режима:

| Режим | Идея | Настройки |
|---|---|---|
| Равномерный | текущая посадка с дистанцией | плотность/га, min distance, seed |
| Кластеры | отдельные рощи с повышенной локальной плотностью | средний радиус рощи (м), разброс радиуса, число центров/га, сила сгущения, минимальная дистанция |
| Смешанный | рощи + одиночные деревья + поляны | доля кластеров, интенсивность/размер полян, минимальный разрыв, seed |

Практический алгоритм: один раз построить низкочастотное **поле множителя плотности** (например, smooth value noise/гауссовы кластеры с псевдослучайными центрами), затем использовать его при выборе кандидатов. Формально `λ(x,y) = λ_group × alpha(x,y) × clusterField(x,y)`, где `clusterField` нормализуется по допустимой площади так, чтобы пользовательская средняя плотность не превращалась неожиданно в двойную. *Маска RGB при этом остаётся фильтром допустимости, Alpha — полем плотности.* Поляны — области с пониженным коэффициентом, а не удаление оригинальных пикселей TGA.

Структуры **не заменяют** этот режим: кластеры отвечают за распределение одиночных деревьев, структуры — за заранее авторские композиции. Эти системы могут использоваться одновременно и обязаны учитывать зоны исключения друг друга.

## 8. Фильтры рельефа

Для группы и/или структуры: `minHeight`, `maxHeight` (по Z в метрах игры либо явно локальному уровню), `maxSlopeDeg`, `minSlopeDeg`, по желанию `slopeDirection/Aspect`, `maxHeightVariationInsideFootprint`. Террейн берётся из выбранного mesh объекта Max; все расчёты в игровых метрах (настройка world scale), с учётом world transform и топологии.

Примеры: ели максимум 25°; камни 0–70°; тростник в низине; структуры из упавших деревьев на почти плоских плато. Отдельная опция «Наклонить к нормали» не должна автоматически означать «разрешить на любом крутом склоне» — это **две** разные настройки.

Поверхность нужно брать по пересечению вертикального луча с конкретным mesh террейна (не ближайший объект сцены), рассчитывая нормаль треугольника/интерполированную при необходимости. Если пересечение не найдено — пропуск с записью причины.

## 9. Редактор маски `*_forest.tga`

**Только маска Forest Studio**, а не SDK `_det` или `_mask`. При открытии сравнить базовое имя террейна `terrain_mp_atp` → `terrain_mp_atp_forest.tga`; другие виды масок показывать отдельно как reference, не изменять.

Предлагаемые слои: RGB ID зон (деревья/камни/кустарники), Alpha поле плотности, дополнительные **неразрушающие** вспомогательные поля/маски кластеров и структур. Выбор цвета группы пипеткой; кисть, ластик, заливка, выбор области, сглаживание Alpha, изменение размеров кисти/жёсткости; Undo/Redo, история, «Сравнить с оригиналом».

Две независимые операции кисти: **рисовать RGB** и **рисовать Alpha**, чтобы прозрачность не ломалась от изменения цвета. При сохранении TIFF не использовать: **строго TGA RGBA** без палитровых сюрпризов, корректная ориентация и контроль размера, сохранять исходный `*_forest.tga.bak` и отдельно рабочие слои проекта. Переходные смешанные RGB нельзя интерпретировать как новые биомы: список групп и **реальный** генератор обязаны использовать **одинаковый** алгоритм сопоставления к ближайшему цвету группы с заданным порогом, в отличие от нынешних двух допусков.

Preview должен показывать RGB, Alpha и комбинированную плотность (цвет+прозрачность), прогноз посадки поверх маски и число потенциальных объектов по группам. Редактор не сохраняет маску автоматически при каждом мазке без восстановления; автосохраняется временный проект, а запись `.tga` делается по явному Save/Save As.

## 10. Производительность, ограничения и тесты

- Лёгкие превью: точки/боксы, а не генерация десятков тысяч реальных meshes.
- Spatial hash/grid для исключений, один raycast-кэш по terrain или адаптивная выборка, пакетная подготовка LOD.
- Сценарии тестирования: flat, steep slope, canyon, alpha-gradient, 200k candidates, полное отсутствие ref_name, удалённый исходный `.object`, одинаковые basename в разных папках SDK, сохранение/загрузка структуры после переноса SDK.
- Сравнение золотой сцены по seed: положения/повороты после генерации с одинаковыми параметрами должны совпадать до допуска.
- В проверке `scene_object.part` — валидные ссылки и трансформации, никаких ссылок на JSON структур.
- Регрессия v0.4.6: группы, веса, пресеты, THM, библиотека, удаление, экспорт должны продолжить работать.

## 11. Порядок разработки

1. **v0.5.0 — Structures Library:** новая вкладка, захват выделения, формат JSON, чтение/запись и валидация `ref_name`, предпросмотр, редактирование в сцене. **Пока без массовой посадки структур**, если тесты UX этого требуют.
2. **v0.5.1 — Structures Placement:** частота/га, веса, условия и footprint, индивидуальные нормали, вставка структуры, Undo, слой, метки и экспорт через существующий backend.
3. **v0.5.2 — Terrain Rules + Clustering:** фильтры высоты/уклона; рощи, смешанные поляны и кластеры, seed и Preview.
4. **v0.6 — Mask Editor:** рисование маски, Alpha-кисть, Undo, Save As `_forest.tga`, единый tolerance, диагностика и прогноз.

**Критерий готовности:** сохранённую структуру можно загрузить в новой сцене и в другом SDK с той же относительной иерархией `ref_name`; на наклонном террейне каждый элемент выполняет своё правило привязки, а экспорт в `.part` совпадает с тем, что видно в Max.
